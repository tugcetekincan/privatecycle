# PrivateCycle verification

The web harness is the primary way to see the app run without a device. Expo
serves a `react-native-web` build; Playwright drives it; the database (SQLite
via wa-sqlite) works on web when the COOP/COEP proxy is used.

## Fast path

```sh
npm ci                 # once after dependency changes
npm test               # Jest unit suite (fast, no browser)
npm run typecheck      # tsc --noEmit
npm run smoke:web      # end-to-end + screenshots, ~1-3 min
```

Always verify in that order for code changes. `smoke:web` exits non-zero on
page errors or console errors, seeds data, and writes screenshots.

## Interactive loop

```sh
npm run dev:web        # Expo on :8081, proxy on :8082
```

- Always open **http://localhost:8082** — that is the cross-origin-isolated
  origin where `expo-sqlite` can open its database. Port 8081 does NOT work
  for anything touching data.
- `npm run debug:web` boots the same stack headlessly, prints all console
  output / failed requests, probes the DB through `__privatecycle`, and saves
  `artifacts/screenshots/debug.png`. Use it when smoke fails.
- If the OpenCode desktop browser is connected to this session, use browser
  tools (`browser.tabs.open`, screenshots, clicks) against :8082. Otherwise
  use the Playwright scripts above.

## Deterministic seed data

Demo data is generated by `services/DevSeedService.ts` (126 days ending today,
26–30 day cycles, one estimated ovulation day per cycle, deterministic RNG).
Three ways to use it:

| Action | How |
| --- | --- |
| Seed if DB empty | `http://localhost:8082/?seed=1` |
| Wipe + reseed | `http://localhost:8082/?seed=force` |
| Wipe all data | `http://localhost:8082/?reset=1` |
| From UI | Settings → Developer → Load/Reset Demo Data (`__DEV__` only) |
| From the page | `await __privatecycle.seedDemoData({ force: true })` |

Dev-only globals (web, `__DEV__` only — `services/devGlobals.ts`):

```js
await __privatecycle.DataService.getAllDailyData()
await __privatecycle.DataService.getInsights()
await __privatecycle.DataService.getFertilityForecast()
await __privatecycle.DataService.getIntimateData()
await __privatecycle.BackupService.createBackup()
await __privatecycle.PrivateAccessService.reset()
await __privatecycle.generateDemoDailyData({ endDate: new Date() })
```

The `?seed` query param is consumed before the first screen renders (see
`hooks/useDevSeed.ts`), then stripped from the URL.

## Smoke script internals

`scripts/smoke-web.mjs`:

1. starts `expo start --web` on `SMOKE_EXPO_PORT` (default 8091) in CI mode,
2. starts the header proxy on `SMOKE_PROXY_PORT` (default 8092),
3. launches Chromium via Playwright (390×844 at 2x for design-grade screenshots),
4. opens `/?seed=force`, asserts `self.crossOriginIsolated`,
5. walks Overview (cycle hero, variation, chart, symptom/mood trends),
   Insights (Today focus + personal pattern, pattern cards, phase tips from
   seeded data), Calendar (day modal entry + save/dialog, fertility forecast),
   Settings, and the Notifications web notice,
6. reloads and asserts the calendar entry and mood valence/strength persist in
   the DB,
7. saves a symptom on a clean next-month day, then clears it and asserts the
   row and the grey day mark both disappear,
8. opens the private calendar from Settings → Privacy (resets the PIN via
   `__privatecycle.PrivateAccessService.reset()` first), creates PIN `1234`,
   logs today with protection + a note, screenshots the setup/day modal/
   calendar/change-PIN/lock screens, locks, checks a wrong PIN, unlocks,
   reloads `/private` and asserts the gate reappears and the entry survives,
9. fails on page errors / console errors, then kills the whole process tree.

Both scripts fail fast if their ports are occupied and kill Expo's process
group on exit. If a run is interrupted, verify ports are free:
`curl -s -o /dev/null -m 1 http://127.0.0.1:8091 && echo busy || echo free`.

## Known noise vs real errors

Benign and ignored by default: React DevTools banner, `shadow*` style prop
deprecation, `props.pointerEvents` deprecation, favicon 404s. Anything else in
`consoleErrors` / `pageErrors` is a failure — read
`artifacts/smoke-failure.txt`.

## Common failure modes

- **SQLite hangs / worker blocked** — you are on :8081, or the COOP/COEP
  headers are missing/duplicated. Use `npm run dev:web` (:8082) and
  `scripts/lib/web-proxy.mjs`; the proxy replaces headers case-insensitively.
  Verify with `self.crossOriginIsolated === true` and
  `__privatecycle.DataService.getAllDailyData()`.
- **Port in use** — a previous run left a server. The scripts fail fast; kill
  the process or switch ports via `EXPO_PORT`/`PROXY_PORT` or
  `SMOKE_EXPO_PORT`/`SMOKE_PROXY_PORT`.
- **First bundle is slow** (~30 s, 2400 modules) — timeouts in the scripts are
  sized for it; don't shrink them.
- **Web ≠ native** — date pickers, share sheet, file system, permissions and
  haptics differ. For those flows use the `privatecycle-mobile` skill.

## Unit tests

`npm test` runs Jest (`jest-expo` preset). Existing coverage: backup envelope
and validation, bulk restore, private calendar backup inclusion/preservation,
seed generator determinism, date-key formatting, fertility forecast math,
dialog component, cycle trends/phase tracks, narrative cards, today tips,
notification settings/planner/screen, private-access PIN hashing/lockout and
intimacy summaries.
Native/Expo modules are mocked in `jest.setup.js`; add mocks there rather than
in individual test files. Tests live in `__tests__/`. Prefer extraction of pure
logic (like `DevSeedService`) so it can be tested without the DB.
