04 / DECISION SUMMARY

What each direction buys — and costs

All three are correct on data. The choice is about how much guidance the dashboard should carry before the first period start.

A

Smallest visual change

Fastest to ship. Keeps the current dashboard shape and replaces missing values in place. Repeats empty boxes and asks for the same first step in several places.

B

Clearest hierarchy

Recommended. Leads with one warm action, then each section earns its place as data arrives. Moderate layout work and the least repetitive empty-state noise.

C

Most explicit roadmap

Most instructional. Shows exactly what each view needs. Busier: more state rules, more UI, and more places to keep requirements in sync.

SHARED REQUIREMENTS

Prerequisites, stated exactly

No vague “after a few cycles” copy and no invented defaults. Missing data stays visible as missing.

1 A period startThe first day of a separate period — not each bleeding day.
2 2 period startsOne measured cycle, which makes cycle length possible.
3 3 period startsVariation and cycle comparisons become possible.
4 2 complete bleeding runsTypical period length. One run is not enough.
5 5 mood-rated days in 60A mood trend can appear. Recent ratings stay visible before then.
6 Pattern qualificationSymptom: 3+ phase-linked days, 50%+ in one estimated phase. Mood: 2+ mood days in each of 2+ estimated phases, an average rating in each, and a difference of 0.4+. Not a guaranteed quota.
Keep the later phase-uncertain state distinct. With period history, when the expected end passes without a new start, show phase uncertain / period overdue. That is not a first-use empty state and should not be collapsed into one. Phase context is always estimated, never a proven phase.
Every CTA in these directions is a proposed handoff to the existing Calendar day sheet or the existing backup import. No new forms in Overview or Insights. Log only what you know; nothing here requires daily completion.
